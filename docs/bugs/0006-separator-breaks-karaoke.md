# BUG-0006 空格和标点没有时间就整行退回逐行

- 发现：2026-10-23 / 版本 0.3.3 之后的 main / 全平台
- 现象：采用的逐字歌词里，词与词之间有空格、行尾有标点，或者前一个词的结束晚了几毫秒，整行就退回整行高亮。
- 复现步骤：QRC/TTML 来源的「夜が　明ける」：两个词各有时间，中间的全角空格没有。显示那边判定覆盖不全。
- 根因：来源不给分隔符时间、相邻单位常有几毫秒重叠；`jp_corpus::display_timeline::for_line`（以及前端 `charTimeline`、Swift 的同一规则）要求每个字被覆盖、单位不重叠，而入库时原样保存。
- 影响面：所有带空格或标点的逐字歌词行。
- 修复：☑ 根因修复（与本档案同一提交；`jp_corpus::word_timing::normalize` 在入库时把只含空白/标点的空当并进相邻单位，重叠时截短前一单位的结束，不造新时间） ☑ 自动化测试（`rust/crates/jp-corpus/src/word_timing.rs` 的 normalize / insert_lrc 测试）
- 清理条件：无临时兼容层；已经入库的旧数据重新采用一次即可
