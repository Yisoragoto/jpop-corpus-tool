# 逐字歌词来源与升级

刮削页现在可点「一键补全逐字歌词」处理全库。导入页默认勾选「导入后自动补歌词，优先逐字」，导入结束后加入同一个后台队列；切页不丢进度，可停止。已有逐行歌词也会尝试升级；只有原来没有歌词时才允许逐行回退，已有歌词不会被普通 LRC 替换。来源没有真实逐字数据时仍保持逐行。

批量采用还要求歌名、歌手身份一致、有效音频时长、现有正文相似度至少 97%，并比较经过播放器验证的真实逐字覆盖率。人工导入/编辑/恢复的歌词及手动时间校准不会被批量覆盖；不确定的结果列为待复核，仍可逐首预览。采用前在写事务里重新检查当前歌词、校准和人工修改状态，停止后未写入的候选会丢弃。批量队列对同一个网站两次请求至少隔 600ms（跨歌共享），整库两百首大约 20 分钟。QQ／酷狗正文开头的「曲名 - 歌手」行和开头、结尾连成一段的乐手署名（「E. Guitar：…」「编曲：…」）在取回时就去掉，不当歌词进库，也不参与 97% 的正文比对；比对和逐字覆盖率都按入库整理（空格标点并入相邻单位）之后的样子算。


批量补齐、导入后获取与单首补齐现在共用高精度优先的获取逻辑。已有逐行歌词的歌不需要先清空：选歌，点「搜索逐字歌词」，查看候选的来源、格式、真实逐字行数和正文预览，再点「采用」。单首曲目的歌词工具里也有同一入口。

候选只在内存缓存 20 分钟。搜索不写歌词；采用时重新检查当前歌词和校准是否仍与搜索时一致。正文明显不同或时间超出本地音频的候选不展示，接口失败和未找到分开说明。平台上名字相同仍可能是不同录音，采用前应核对版本，采用后试听。

## 来源

- 网易云：尝试公开响应中的 YRC；当前样本只返回普通 LRC 时，明确提供逐行回退，不调用要求额外授权的私有接口。普通 LRC 不当作逐字歌词。
- QQ 音乐：QRC。
- 酷狗：KRC。
- 说明：QQ 音乐和酷狗没有公开的歌词 API，这两个来源走的是它们客户端用的非公开接口（QQ 要带客户端式的请求头，酷狗的请求要签名），没有官方授权，随时可能失效或被拒；只在本机读取、供个人学习，不缓存或分发正文。
- AMLL 社区库：按歌曲平台 ID 查 TTML。原始文件域名不可达时，只回退同仓库的 GitHub 官方 Contents API，仍受 GitHub 限额；不使用第三方代理。社区收录不保证覆盖所有日语歌，也不保证适合不同版本的本地音频。
- LRCLIB：使用官方 `get/search`，读取 `syncedLyrics`、`plainLyrics`、`duration`、`trackName`、`artistName`。只有正文实际包含可验证的 Enhanced LRC 标记才按逐字处理；普通返回值仅为逐行/纯文本候选，不分配字符时间。
- Apple Music：可选、默认关闭，使用官方 `api.music.apple.com` 目录 API 搜索元数据、ISRC 和封面。官方文档未提供歌词正文或逐字端点，`hasLyrics` 仅是目录标志。不会调用私有歌词接口；已有合法取得的 TTML 可手动导入。

来源开关与 Apple 商店地区保存在当前库的 `lyric-sources.json`；Apple Developer Token 仅留在后端内存，关闭程序后清除，不存配置文件或 localStorage，也不回显令牌原文。目录查询不需要 Music User Token。旧 IPC 中的该字段只为兼容保留，不发送给网络。

这是对各平台现有接口的独立适配，接口可用性与曲目覆盖会变化；不依赖来历不明的公共转发服务。协议实现参考的第一手资料：

- [LDDC](https://github.com/chenmozhijin/LDDC)：多来源歌词获取与格式说明。
- [AMLL 逐词歌词库](https://github.com/amll-dev/amll-ttml-db) 与 [格式文档](https://amll.dev/en/guides/lyric/formats)。
- [MusicKit hasLyrics](https://developer.apple.com/documentation/musickit/song/haslyrics)：是否有歌词的标记，不代表公共 API 提供正文。
- [Apple Music API](https://developer.apple.com/documentation/applemusicapi)：目录及认证能力。
- [LRCLIB API](https://lrclib.net/docs) 与[服务端源码](https://github.com/tranxuanthang/lrclib)：实际响应字段与格式。

## 时间轴与版本

格式解析统一为行、Unicode 字符区间、开始与结束时间。不会把整句按字数均摊后声称是源提供的逐字时间；来源只细到一个词时，也不编造词内每个字的时间。

入库时先整理一遍（`jp_corpus::word_timing::normalize`），不造新时间：单位之间、行首行尾只有空白和标点的空当并进相邻单位，前一单位的结束晚于后一单位的开始时截到后一单位开始。播放器按行判断：完整、单调、不重叠、起止有效且覆盖原文的已知来源单位，才做卡拉 OK；一个单位里的几个字画成一道从左到右扫过去（只是画法，时间仍是单位的起止）；词段内的字符共享原始单位时间。缺失或异常的行整行高亮；没有时间的纯文本不高亮。只有起点的手动校准仍可用于定位，不能推算整行动画。行级试听窗口原有的保守结尾只用于切片/AB，不成为逐字时间。

采用后写增强 LRC 与现有 `word_timings` 表，不引入第二套播放时间轴。精确结束时间另保存在表里，避免把休止一律延长到下个词。旧歌词版本保留；老库没有保存原文的歌词，会先生成一份可恢复快照。正文不变的手动校准按「完全相同的行的第几次出现」迁移，不把副歌第二遍的校准误放到第一遍；如果不能保留校准则拒绝替换。已有分词校正继续走按原文恢复的机制。

网络不占用界面的数据库锁。采用在事务中完成；文件写入失败时数据库回滚，数据库提交失败时恢复旧文件。不会改音频文件的标签。

结构版本 20261022 只增加歌词版本的 `raw_format`、`source_raw`、`sync_granularity`、`timing_origin`、`timing_validation_json`。原始来源正文与用于语料分析的规范 LRC 分开保存；来源、获取时间、用户修订继续使用既有版本/修订表。旧库未知精度不冒充原生逐字；数据库迁移和库间迁入都保留时间单位及手动校准。当前版本就是首选，切换版本沿用「恢复」功能并追加历史。

## 元数据与扩展

复用原有 `MetadataProvider` / resolver，歌词和封面另有能力接口，HTTP 继续在阻塞工作线程执行。优先用文件中的 ISRC、MusicBrainz Recording ID 或已知平台编号召回，随后仍验证标题、歌手、录音版本和时长。相同身份且时长/ISRC 不冲突的候选可补充缺失字段，字段来源分别记录；明确的版本/ISRC 冲突交人工确认。已填字段及人工修订不因自动刮削覆盖。

Spotify、Discogs、VocaDB 本次不启用网络适配。Spotify 的官方 Track API 提供元数据/ISRC，不能当歌词 API；还需 OAuth、配额及署名流程。Discogs 适合发行/署名补充而不是逐字时间；VocaDB 适合声库相关曲目，不能用合成歌手名强行匹配真人同名歌。这些能力应先完成凭据与数据使用条件确认再注册 provider，不显示假可用开关。既有 MusicBrainz / CAA / Deezer 继续各自提供结构化资料或图片。

AI 对齐仍未接入，也不引入模型。未来生成时间必须标记为算法来源，未验证前不能进入默认卡拉 OK 时间轴。

## 本地文件

歌词文件选择器支持增强 LRC、YRC、QRC、KRC 和 TTML，普通 LRC/TXT 保持原来的读取方式。二进制格式先解码，再按同一解析器转换。遇到不支持的文件布局会明确报错，不把乱码存成歌词。

## 验证

自动化测试使用合成的日文短句，覆盖格式时钟、Unicode 字符位置、翻译与背景段过滤、XML 实体、逐行冒充逐字、凭据不落盘、过期或已修改的候选、重复行校准保留、历史版本、写文件失败回滚。联网探测只报告来源、是否匹配、行数与错误，不把获取的真实歌词作为仓库测试夹具。

2026-10-22 实际端到端验证（公开样本「夜に駆ける / YOASOBI」，261 秒）：从来源检索、解码、解析、兼容性检查，到临时隔离库采用与播放器时间轴验证均已运行。QQ 为 67 行正文 / 64 行有效卡拉 OK；酷狗为 86 / 85；AMLL 为 56 / 56。歌词署名按原有导入规则分离；缺失或异常的行保持逐行，不补时间。下载样本只在测试进程和临时目录处理，结束后删除，不写测试夹具或用户库。单曲验证不代表全曲库覆盖。

显式复测：在 `rust` 目录执行 `cargo test -p jp-app --lib public_sources_attach_real_units_to_an_isolated_library -- --ignored --nocapture`。此测试依赖网络，默认测试不运行它。三个客户端使用同一份 15 案例时间轴 fixture；Windows 已运行 Rust 和 TypeScript，Swift 测试需在 macOS 上运行。Apple 没有提供凭据，只验证官方目录的无凭据 401 边界和模拟响应，不宣称已验证认证后的访问。
